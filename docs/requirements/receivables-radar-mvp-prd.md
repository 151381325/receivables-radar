# 回款雷达 MVP 产品需求文档

**版本：** 1.0  
**日期：** 2026-09-12  
**状态：** 已确认，待开发验收  
**目标用户：** 个人自由职业者（单人使用）

## 1. 产品概述

回款雷达是一款本地优先的轻量网页工具，帮助个人自由职业者完成“记录应收—安排跟进—登记到账—关闭应收”的回款管理闭环。

产品不试图替代财务、CRM 或合同系统。它只解决一个高频问题：用户每天打开页面时，能迅速知道哪笔款该先处理，并以尽量少的操作推进回款。

## 2. 目标与成功标准

### 2.1 产品目标

- 让用户用最少字段建立一笔可跟进的应收记录。
- 把逾期、承诺付款日已过、到期和待跟进的款项自动排成今日行动。
- 支持从催款沟通到部分到账、全额到账的完整记录。
- 不要求注册、配置账号或学习财务术语。

### 2.2 成功标准

用户可以在一次使用中完成以下闭环：

1. 新建一笔应收。
2. 在“今日行动”中找到需要处理的记录。
3. 生成并复制催款文案，随后自行通过微信或其他渠道发送。
4. 记录沟通结果及下一次跟进时间。
5. 登记部分或全部到账；全额到账后由系统自动关闭。

## 3. 用户与使用场景

### 3.1 目标用户

- 独立设计师、开发者、顾问、摄影师、文案等个人自由职业者。
- 有多笔项目款、尾款或顾问费需要持续跟进的个体服务提供者。

### 3.2 典型场景

| 场景 | 用户需求 | 产品响应 |
|---|---|---|
| 新项目产生应收 | 快速把该收的钱记下来 | 用客户、项目、金额、截止日建立记录 |
| 今天需要催款 | 不想逐笔翻台账 | 首页仅列出今天真正要处理的应收 |
| 客户承诺某日付款 | 避免忘记再次跟进 | 保存承诺付款日和下一次跟进日 |
| 客户分次付款 | 清楚知道还差多少 | 累计到账、自动计算剩余金额和状态 |
| 更换浏览器或担心丢数据 | 保留自己的台账 | 导出和导入 JSON 完整备份 |

## 4. MVP 范围

### 4.1 包含功能

- 应收的新建、编辑、删除和列表查看。
- 今日行动、全部应收、状态筛选。
- 应收状态、剩余金额、逾期天数和优先级的自动计算。
- 跟进记录、客户承诺付款日和下次跟进日。
- 部分到账、全额到账与到账时间线。
- 分阶段催款文案的生成、编辑和复制。
- JSON 完整备份和合并恢复。
- 付款截止日、下次跟进日的 `.ics` 日历提醒导出。
- 首次使用的示例数据及空状态引导。
- 手机与桌面浏览器的自动响应式适配。

### 4.2 明确不包含

- 注册、登录、账号体系、云同步或多设备实时同步。
- 多人协作、角色权限、客户门户。
- 微信、邮件、短信等渠道的自动发送。
- 支付、发票开具、合同、附件、联系人管理。
- CSV 导入导出、复杂报表、搜索、批量操作和 AI 功能。

## 5. 核心流程

```text
新建应收 → 今日行动提示 → 跟进/生成文案 → 记录沟通
                                      ↓
                                  登记到账
                                      ↓
                         部分到账继续跟进 / 全额到账自动关闭
```

## 6. 功能与业务规则

### 6.1 应收记录

新建时必填：客户名称、项目名称、应收金额、付款截止日。

可选：是否已发送发票或付款通知、下次跟进日、备注。编辑既有记录时可设置“暂停跟进”。

金额以人民币元计，保留两位小数。应收总额不得小于已累计到账金额。

### 6.2 状态规则

| 条件 | 状态 | 说明 |
|---|---|---|
| 累计到账金额等于应收总额 | 已收款 | 优先级最高，自动关闭 |
| 用户勾选暂停跟进且未全额到账 | 暂停跟进 | 保留在台账中，但不进入今日行动 |
| 已到账但未全额到账 | 部分到账 | 继续跟进剩余金额 |
| 未发送发票或付款通知 | 待开票 | 需要推动付款资料或通知 |
| 其余未收款记录 | 待付款 | 等待或跟进付款 |

### 6.3 今日行动规则

首页只显示当日确实需要处理的未关闭、未暂停记录。优先级从高到低：

1. 客户承诺付款日已过。
2. 已超过付款截止日。
3. 已到下次跟进日。
4. 当天到期。
5. 待开票且未设置下次跟进日。

未来到期且未达到跟进日的记录不应进入今日行动，但应在“全部应收”中可见。

### 6.4 跟进与到账

- 跟进记录包括：跟进日期、沟通结果、可选的客户承诺付款日、可选的下次跟进日。
- 到账记录包括：到账金额、到账日期、收款方式、可选备注。
- 单次到账金额不得超过当前剩余金额。
- 应收详情按时间倒序展示到账和跟进记录。

### 6.5 催款文案

系统按记录状态生成可编辑文案，覆盖：到期前、逾期 1—3 天、逾期 4—7 天、逾期超过 7 天、承诺付款日已过。

文案必须带入客户名称、项目名称、剩余金额与相关日期。用户自行复制并通过自己的沟通渠道发送；系统绝不自动发送。

### 6.6 数据与备份

- 应收数据仅存储在当前浏览器中。
- JSON 导出必须包含版本、导出时间和全部记录。
- 导入前必须校验格式；错误文件不得覆盖现有记录。
- 对 ID 重复的记录采取跳过策略，并告知导入与跳过数量。

## 7. 页面与交互

### 7.1 今日行动页

展示待收总额、逾期金额、今日行动笔数与 7 天内到期金额。行动卡片展示客户、项目、剩余金额、状态及行动原因；点击后进入详情。

首页应使用“方案 B：温暖陪伴”的视觉方向：以明确的行动建议降低用户对催款的心理负担，但金额、逾期和主操作保持高可见性。

### 7.2 全部应收页

展示完整台账，支持按待开票、待付款、部分到账、已收款、暂停跟进筛选。未关闭记录优先显示。

### 7.3 新建与编辑

默认只呈现最低必要字段；高级信息保持可选。用户不手动选择业务状态，状态由系统计算。

### 7.4 应收详情与弹窗

详情显示剩余待收、已收金额、当前状态、关键日期和完整时间线。用户可直接发起跟进、登记到账、生成催款文案、编辑或删除。

删除操作必须获得明确二次确认。

### 7.5 响应式要求

- 同一页面根据屏幕宽度自动切换布局；最终用户无需点击“手机版/网页版”开关。
- 手机端采用单列和底部导航，主要操作应方便单手触达。
- 桌面端可使用更宽的信息布局和顶部导航。
- 正文不小于 14px，主要可点击区域不小于 44px，不产生横向滚动。

## 8. 验收标准

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| AC-01 | 快速建账 | 可用 4 个必填字段完成创建并在列表中看到记录 |
| AC-02 | 今日行动 | 仅显示当日需处理记录，按承诺超期、逾期、跟进日、到期等优先级排序 |
| AC-03 | 跟进闭环 | 可保存沟通结果、承诺付款日与下次跟进日 |
| AC-04 | 到账闭环 | 支持部分与全额到账，自动更新剩余金额和状态 |
| AC-05 | 催款辅助 | 可生成、编辑和复制不同阶段的催款文案，不自动发送 |
| AC-06 | 数据安全 | 可导出 JSON；非法导入不覆盖现有数据；重复 ID 有明确统计 |
| AC-07 | 日历提醒 | 可导出付款截止日或下次跟进日的 `.ics` 文件 |
| AC-08 | 易用性 | 在手机和桌面宽度下自动适配，关键操作清晰可用 |
| AC-09 | 视觉方向 | 首页和行动卡片采用“温暖陪伴”方案，保持金额与风险提示的可读性 |

## 9. 风险与边界

- 清理浏览器数据、使用无痕模式或更换设备可能造成数据不可用；用户应定期导出 JSON 备份。
- 因无账号与云同步，产品不能保障多设备间的数据一致性。
- 催款内容由用户自行审核和发送，产品不承担沟通结果或款项回收责任。
- 用户不应在备注中录入银行卡号、身份证号、密码等敏感信息。
