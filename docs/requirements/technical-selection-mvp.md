# 回款雷达 MVP 技术选型结论

**日期：** 2026-09-12  
**状态：** 已确认

## 1. 结论

MVP 采用无框架的静态网页架构：HTML5、CSS3、原生 JavaScript ES Modules、浏览器 LocalStorage，以及 Node.js 内置测试运行器。

不引入后端、数据库、账号系统、第三方服务或构建工具。

## 2. 选型目标

- 用户打开网页即可使用，不注册、不配置。
- 保持部署、维护和后续迭代成本最低。
- 支持手机和桌面自动响应式布局。
- 在本地完成应收、跟进、到账、备份和日历导出闭环。

## 3. 架构边界

| 层级 | 方案 | 职责 |
|---|---|---|
| 页面层 | HTML + CSS + `src/app.js` | 页面渲染、事件和交互状态 |
| 业务层 | `src/domain.js` | 状态、金额、日期、队列和仪表盘规则 |
| 数据层 | LocalStorage + `src/storage.js` | 当前浏览器的本地持久化 |
| 工具层 | 备份、日历、文案模块 | JSON 备份恢复、ICS 导出、催款文案 |
| 测试 | Node.js `node --test` | 业务规则与工具模块回归测试 |

## 4. 选择原因

| 决策 | 原因 |
|---|---|
| 原生 JavaScript | 当前功能规模有限，避免框架、打包和依赖管理带来的额外复杂度 |
| LocalStorage | 满足单人、单浏览器 MVP；无需服务器和账号体系 |
| ES Modules | 以清晰模块边界隔离页面、业务规则、存储和工具能力 |
| JSON 备份 | 为本地数据提供最简单、可移植的恢复手段 |
| ICS 导出 | 不接入外部日历账号，仍可让用户添加本地日历提醒 |
| Node 内置测试 | 无外部测试依赖，适合验证金额、日期和状态等关键规则 |

## 5. 已知限制

- 数据只存在当前浏览器；换设备、清理浏览器或无痕模式不保证数据保留。
- 不支持多人协作、权限、审计或实时同步。
- 不支持自动发送微信、邮件或短信。
- 没有服务端备份、登录鉴权和跨设备冲突处理。

## 6. 后续版本的升级路径

当 MVP 获得稳定使用后，再根据真实需求评估：

1. 账号与云端数据同步。
2. 加密备份与跨设备恢复。
3. 多项目、联系人、合同和发票关联。
4. 可控的消息渠道提醒或自动化。
5. 更完整的回款报表。

在没有明确的真实使用需求前，不提前引入上述复杂度。
