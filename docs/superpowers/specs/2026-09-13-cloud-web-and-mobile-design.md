# 回款雷达云端网页版与移动 App 设计

**日期：** 2026-09-13  
**状态：** 已完成讨论，待用户审核  
**适用范围：** 中国大陆个人自由职业者，单人账号使用  
**现有基线：** 回款雷达本地静态 MVP 0.1.0

## 1. 目标

在保留现有应收、跟进、到账、催款文案和响应式界面的基础上，将产品升级为支持账号登录、云端存储和电脑/手机数据同步的正式网页版。网页版稳定后依次交付 PWA、Android App 和应用商店版本；iOS 在 Android 稳定后单独立项。

产品继续遵循“功能够用、操作简单”的原则。首个云端版本不增加团队协作、审批、支付、自动发送催款消息或复杂报表。

## 2. 交付边界

### 2.1 包含

- 邮箱注册、邮箱验证、密码登录、退出和找回密码。
- 安全会话、账号注销、个人数据导出和删除。
- 应收、跟进、到账和关键日期的云端存储。
- 电脑及手机浏览器之间的数据同步。
- 旧版 LocalStorage 数据的确认式导入。
- 独立域名、HTTPS、ICP备案和正式网页版部署。
- PWA 安装、网络状态提示和基础缓存。
- 使用 Capacitor 打包 Android App。
- 基于付款截止日和下次跟进日的 Android 本地通知。
- Android 上架需要的隐私、备案、软著和商店材料。

### 2.2 不包含

- 手机短信、微信、支付宝或其他第三方登录。
- 多人共享、组织、角色和审批。
- 自动发送微信、短信或邮件催款。
- 在线支付、开票、合同和附件管理。
- 服务端实时推送、复杂离线编辑和字段级冲突合并。
- 首期 iOS 开发与 App Store 上架。

## 3. 分阶段交付

| 阶段 | 交付结果 | 验收条件 |
|---|---|---|
| M1 基础设施 | 腾讯云服务器、域名、测试环境和备案申请 | 服务器安全基线完成，测试入口可访问 |
| M2 云端核心 | API、数据库、注册登录和权限隔离 | 两个测试账号的数据完全隔离 |
| M3 业务迁移 | 现有功能接入 API，支持旧数据导入 | 核心流程通过，导入无数据丢失或重复 |
| M4 正式网页 | 正式域名、HTTPS、备份、协议和监控 | 电脑与手机浏览器可登录且数据一致 |
| M5 PWA | 桌面图标、基础缓存和网络状态 | Android 可从桌面独立启动并正确提示离线 |
| M6 Android 测试版 | APK、本地通知和安全存储 | 多台真实手机完成核心流程和升级测试 |
| M7 Android 上架 | APP 备案、软著和商店审核材料 | 至少一个适合个人开发者的商店正式可下载 |
| M8 iOS | 单独设计、开发和审核 | Android 稳定后另行批准范围 |

每个里程碑独立验收。外部备案、软著和商店审核时间不计入纯开发工期。

## 4. 总体架构

### 4.1 云资源基线

- 云厂商：腾讯云。
- 产品：轻量应用服务器，中国大陆上海地域。
- 规格：2 核 CPU、2GB 内存、40–50GB SSD，包年购买。
- 操作系统：Ubuntu 24.04 LTS。
- 升配条件：持续内存不足、数据库增长或真实并发超过现有规格承载范围时再评估，不提前拆分服务。

### 4.2 软件组件

| 组件 | 技术 | 单一职责 |
|---|---|---|
| Web | 现有 HTML/CSS/JavaScript ES Modules | 页面、交互和响应式布局 |
| API | Node.js + Fastify | 鉴权、业务接口、校验和权限控制 |
| Database | PostgreSQL | 账号、应收、跟进、到账、会话和软删除数据 |
| Reverse Proxy | Caddy | HTTPS、静态资源、反向代理和安全响应头 |
| Deployment | Docker Compose | 统一启动 Web、API、数据库和备份任务 |
| Mobile | PWA + Capacitor | 复用网页代码并接入 Android 原生能力 |

MVP 使用单服务器部署。PostgreSQL 只在 Docker 内部网络可见，不开放公网端口。公网仅开放 HTTP、HTTPS 和受限 SSH。

### 4.3 域名路由

首版使用一个主域名：网页位于 `/`，API 位于 `/api`。隐私政策、用户协议和账号注销说明使用同域公开页面。该方案减少子域、跨域 Cookie 和证书配置；有独立官网需求时再拆分 `www`、`app` 和 `api` 子域。

## 5. 账号与会话

### 5.1 注册和登录

- 注册字段仅包含邮箱、密码和对协议的明确同意。
- 注册后发送限时邮箱验证码；验证成功后账号可正常使用。
- 登录使用邮箱和密码。
- 找回密码通过限时、单次有效的邮箱重置链接完成。
- MVP 不提供短信和第三方登录。

### 5.2 密码和会话安全

- 密码使用 Argon2id 生成不可逆哈希，数据库不保存明文密码。
- 登录会话通过 `HttpOnly`、`Secure` Cookie 传递，并设置合适的 `SameSite` 策略。
- 登录、注册、验证码和重置密码接口设置 IP 与账号维度的频率限制。
- 用户退出时使当前会话立即失效；修改密码和注销账号时使全部会话失效。
- 移动 App 的敏感会话信息存入系统安全存储，不写入普通 LocalStorage。

## 6. 数据模型与隔离

主要实体为：用户、会话、应收、跟进记录、到账记录和数据导入批次。

- 每条业务记录必须包含 `user_id`。
- API 的所有读写在服务端同时按记录 ID 和当前 `user_id` 查询。
- 前端隐藏记录或按钮不作为权限控制手段。
- 金额继续以人民币元显示，数据库使用精确小数或整数分存储，禁止浮点金额计算。
- 每条可修改记录包含创建时间、更新时间和软删除时间。
- 应收总额不得小于累计到账；单次到账不得超过当前剩余金额。
- 现有状态、今日行动和催款文案业务规则保持不变，由共享规则和服务端校验共同保障。

## 7. 数据同步与迁移

### 7.1 正常同步

- 云端 PostgreSQL 是正式数据源。
- 新增、编辑、跟进和收款操作须在 API 成功后显示“已同步”。
- 网络失败时界面明确显示“尚未同步”，并保留可重试操作。
- MVP 使用记录级最后成功写入优先，并通过更新时间或版本号拒绝明显的旧版本覆盖。
- 不实现复杂的字段级合并；发生冲突时提示用户刷新并重新确认修改。

### 7.2 旧数据导入

1. 用户首次登录后，前端检测旧版 LocalStorage 数据。
2. 页面说明发现的数据数量，由用户决定是否导入。
3. 导入前自动下载一份 JSON 备份。
4. API 校验备份版本、字段、金额、日期及关联关系。
5. 使用原记录 ID 与当前用户 ID 组合去重，相同记录跳过并返回统计。
6. 导入成功后暂时保留本地数据；用户核对云端数据后手动清除。
7. 任一批次出现结构性错误时整批回滚，避免半导入状态。

## 8. 删除、注销与备份

- 普通记录删除采用软删除，保留 30 天后永久清理。
- 用户可导出结构化个人数据，导出内容不包含密码哈希和会话信息。
- 账号注销需要重新验证身份并二次确认；注销后立即禁止登录。
- 注销账号的业务数据进入 30 天待删除期，期满永久清理；法律法规要求保留的安全日志按隐私政策单独说明。
- PostgreSQL 每日生成加密备份并保存到腾讯云对象存储，至少保留 7 天。
- 每月执行一次恢复演练，记录恢复时间和核对结果。

## 9. PWA 与 Android App

### 9.1 PWA

- 增加 Web App Manifest、图标和 Service Worker。
- 缓存应用外壳和必要静态资源，不缓存含用户敏感数据的 API 响应。
- 离线时允许查看应用壳并明确显示网络不可用；不承诺完整离线编辑。
- 页面继续根据屏幕宽度自动切换布局，不提供手机版/网页版手动开关。

### 9.2 Android

- 使用 Capacitor 封装同一套 Web 代码和 API。
- 首版原生能力仅包括网络状态、安全存储和本地通知。
- 根据付款截止日和下次跟进日安排本地通知；日期修改、记录关闭或删除时同步更新或取消通知。
- 新设备登录并同步完成后重新计算未来通知。
- 用户拒绝通知权限时不影响业务功能，首页继续显示今日行动。
- 不申请通讯录、短信、通话记录、精确位置等与产品无关的权限。

服务端推送和 iOS 均不属于本设计的首期实现。

## 10. 部署与安全

- 腾讯云安全组仅开放 `80`、`443` 和受来源限制的 `22` 端口。
- SSH 使用密钥登录，禁用密码登录和直接 root 远程登录。
- Caddy 自动签发和续期 HTTPS 证书，并配置基础安全响应头。
- 数据库账号遵循最小权限，生产密钥通过服务器环境配置注入。
- `.env`、密钥、邮箱授权码、证书和备份文件不得提交到 GitHub。
- API 对所有输入执行类型、长度、金额和日期校验，并返回统一错误结构。
- 日志不得记录密码、验证码、完整 Cookie、重置令牌或用户备注正文。
- 依赖和操作系统定期安装安全更新；上线前进行依赖漏洞检查。
- 部署前备份数据库；健康检查失败时回滚到上一稳定应用版本。

## 11. 合规与外部前置条件

- 域名注册人与备案主体保持一致，使用用户本人实名认证账号购买服务器和域名。
- 中国大陆正式开放前完成网站 ICP 备案；APP 发布前按届时有效要求完成 APP 备案。
- 网站正式开放后按适用要求办理公安联网备案。
- 注册页和应用商店页面均提供隐私政策、用户协议和账号注销说明。
- 隐私政策列明收集字段、目的、保存期限、第三方服务、导出和删除方式。
- 应用商店数据收集声明必须与实际代码和第三方 SDK 行为一致。
- 商店、软著和备案规则可能变化，提交前以主管部门及目标商店的当期规则复核。
- 付款、实名认证、备案提交和正式外部发布均由用户最终确认并操作或明确授权。

## 12. 错误处理与可观测性

- API 使用稳定错误码区分校验失败、未登录、无权限、冲突、频率限制和服务器错误。
- 界面使用可执行的中文提示，不向用户展示堆栈、SQL 或内部路径。
- 每 5 分钟检查网页和 API 健康状态。
- 监控 CPU、内存、磁盘、数据库连接和容器状态，并在异常时告警。
- 应用日志使用请求标识关联问题，但避免记录业务敏感正文。
- 邮件发送失败可重试，并对验证码和重置链接设置明确有效期。

## 13. 测试与验收

### 13.1 自动测试

- 保留现有领域规则、存储、备份、日历和文案测试。
- 增加 API 注册、登录、会话、找回密码和频率限制测试。
- 增加应收、跟进、到账、软删除和数据冲突测试。
- 增加两个用户之间的横向越权测试。
- 增加旧数据正常导入、重复导入、损坏文件和整批回滚测试。
- 增加数据库迁移与备份恢复验证。

### 13.2 人工验收

- Windows Chrome/Edge 和 Android Chrome 完成全部核心流程。
- 同一账号在电脑和手机上修改后数据一致。
- 网络中断时明确显示未同步，恢复后可以重试。
- PWA 可安装、更新和卸载，不缓存敏感 API 数据。
- Android 真机完成登录、同步、通知授权、日期变更、关闭应收和应用升级。
- 隐私政策、用户协议、注销和数据导出入口均可正常访问。

## 14. 实施顺序与依赖

1. 购买服务器和域名，启动实名及备案准备。
2. 建立后端、数据库、测试环境和自动化部署基础。
3. 完成账号、会话和数据隔离。
4. 将现有业务能力逐步接入 API。
5. 完成旧数据导入、备份、恢复和安全加固。
6. 备案通过后上线正式网页版并进行真实使用验收。
7. 网页稳定后交付 PWA，再交付 Android APK。
8. 完成 APP 备案、软著和目标商店材料后提交审核。
9. Android 稳定后另行设计 iOS 版本。

建议开发周期为五周：前三周完成云端核心与迁移，第四周完成网页版验收，第五周完成 PWA 和 Android 测试版。备案、软著和商店审核为独立外部周期。

## 15. 成功标准

- 用户可在电脑和手机浏览器使用同一账号登录。
- 同一账号在不同设备看到一致的应收、跟进和到账数据。
- 不同账号之间无法相互访问数据。
- 旧版本地数据可备份并一次性安全导入。
- 网络、冲突和保存失败状态对用户清晰可见。
- 正式站点使用独立域名和 HTTPS，具备有效备份及恢复能力。
- PWA 和 Android 复用同一业务界面，保持方案 B 的暖色视觉与大字号。
- Android 上架前完成适用的隐私、备案和商店材料。
