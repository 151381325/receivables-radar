# 网页资源版本控制（本地待发布）

## 目的与边界

本轮针对“APK已升级但仍显示旧UI、旧导出提示”的问题。用户清空缓存后已恢复，本轮防止后续发布重复出现；不修改登录、业务数据、原生包名/签名、APP桌面图标或数据库。

用户先授权本地实现与验证，完成后通过“继续”确认推进发布。线上是否生效以服务器构建、重建web及HTTP检查为准，不能把Git推送当作部署完成。

## 实现

- `scripts/site-build.mjs` 对完整 src 目录的排序路径和文件内容计算SHA256，取16位作为资源目录版本。
- 构建输出包含 `/assets/<版本>/src/` 完整资源树，HTML中的样式和入口脚本切换到该目录。模块的相对导入、动态导入和CSS图片路径沿用目录关系，因此间接依赖也被版本隔离。
- 相同源文件重复构建保持资源URL；任何源资源变化都会生成新目录。
- 原 `/src/` 保留，兼容已打开的旧页面；源码HTML保持开发路径不变。
- Caddy的HTML入口和旧路径使用 `Cache-Control: no-cache`，允许缓存但每次重新校验。
- 实际存在的版本化资源使用一年immutable缓存；缺失资源返回404和no-store，不回退HTML。
- `/api/`代理行为未修改，不给账号或业务API新增长期缓存。

## 发布与使用说明

确认发布后只需更新web构建和Caddy配置，不需要迁移数据库或重新安装APP。更新资源在页面重新打开/刷新时生效，不在用户编辑过程中强制刷新。

首次启用新缓存策略不能追溯清除其他设备已经缓存且未过期的旧HTML；这些设备仍可能需要一次刷新。此后进入版本化发布流程的客户端在下一次导航时会校验首页并加载新资源。

每次构建当前只包含当次版本的资源，不跨发布保留所有历史目录。长时间停留旧页面后才发起动态加载，可能需要重新打开页面；不要在生产升级时承诺旧页面永不失效或完整离线运行。
